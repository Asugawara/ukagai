# public/

The GUI served by `ukagai serve`. Static files, no build step. `GET /` returns `index.html` (and issues the cookie); everything else is under `/public/*`.

- `index.html` — the skeleton (left "background", right "decision", empty state, banner, drawer for the pending list; toasts are created by `app.js`). Static text carries `data-i18n="<key>"` / `data-i18n-aria-label="<key>"` and is replaced at startup.
- `i18n.js` — ES module with `MESSAGES = { en, ja }`, `t(key, vars?)` and `applyStatic()`. Both languages must have the same key set (tested). Keys are English snake_case; `{name}` marks a variable.
- `app.js` — ES module. API calls, SSE, rendering. Text from outside is inserted with `textContent`. Every display string goes through `t()`.
- `app.css` — system fonts, two columns (background 3fr / decision 340–520px), one column below 900px (decision first). The pending button switches at 1100px (fixed top right at 1100px and up, inline in the heading row below). Dark mode follows `prefers-color-scheme`.
- `vendor/` — `mermaid.min.js` and `marked.umd.js` (committed; no CDN).

Update vendor with `npm ci`, then `npm run vendor` (copies from `node_modules` to `public/vendor/`).

## Display language (`data-lang`)

The display language is `en` (default) or `ja`. The server reads `<data-dir>/config.json` at startup and injects `<html lang="…" data-lang="…">` into `index.html`; `GET /api/config` returns `{ "lang": "ja" }`. `app.js` reads `document.documentElement.dataset.lang` (anything but `ja` means `en`), applies it to the static text, and renders with `t()`.

- Changing `dataset.lang` at runtime re-renders in place (a `MutationObserver` on `data-lang`). The tests use this instead of reloading.
- Only UI strings are translated. Section headings shown in the right column (the recommendation box, "what you need to do", "scope and reversibility") are the file's own headings, shown as written.
- Explanation files are accepted with English headings (canonical) or Japanese headings (alias). `app.js` keeps constants with the same content as `SECTION`, `BLOCKER_LABELS`, `COLUMN_HAPPENS` and `COLUMN_RISK` in `src/hook/explain.ts`: sections are matched by exact name over all names, then by partial name; table columns by `happens|outcome|起きること` and `risk|リスク`. Keep them in sync.

## Behavior

- One screen: the page does not scroll, only columns do when content does not fit. There is no header (main fills the screen). With 2 or more pending decisions a small "Pending N ← →" button appears and opens the drawer (closed by default). There are no metrics or session list. Under the right column title it shows the branch (`context.branch` is the only context field rendered), the full working directory, reversibility, scope and elapsed time.
- **The GUI builds the decision screen from the explanation file. A raw AskUserQuestion is shown only without an explanation (`attached_via: none`).** The spec is explanation file v2 (`title`, the Recommendation section, the Options table).
  - Right "decision": `title` → Recommendation section (accent frame) → option cards (one per table row; the `(Recommended)` suffix is stripped and the recommended one gets a badge; the "what happens" column is the body, the "risks" column is dimmed) → free text. The original question and `description` are not shown for options matched to the table (an option with no row falls back to its raw label and description; the second and later questions stay raw). The answer is the original `option.label`, not the table's rendering.
  - Left "background": the body minus the Options and Recommendation sections (marked's DOM is cut at h1–h3 and distributed). Without an explanation it shows one line saying the agent wrote none, with the reason in plain text when known.
  - Old-format tables (pros/cons/cost) still work: the second and later columns are shown in order as body text.
  - **Auxiliary context (`context`) is not rendered**, except `branch`.
- **Blocker (waiting for human work; `explanation.type === "blocker"` or `type` in the front matter)**: an orange band ("Waiting for you") above the title, the "what you need to do" section right under it (orange frame, in the right column; code blocks get a Copy button, and key `c` copies the first one via `navigator.clipboard`), then the three fixed cards. No recommendation section means no recommendation box. The left column keeps "why I stopped" and the rest. The drawer row gets an orange "Action" badge. While a blocker is pending, `document.title` is `(N) ukagai · Waiting for you`. The initial cursor is the recommended option (or the fixed "Done. Continue" label), so `Enter` alone resumes.
- **Long text folds** (it does not trigger when the hook's length limits, spec 3.6, are respected). The recommendation box folds at 6 lines (`max-height` on `.rec-body`, faded at the bottom; callouts such as CAUTION / WARNING stay outside the fold, right under it inside the frame, and are always fully visible). "What happens" and "risks" fold at 3 lines per card (`-webkit-line-clamp`). Only overflowing elements get a "Show all ." chip at the bottom right; `.` or a click toggles everything (state is per decision). While expanded the right column scrolls.
- After answering, the GUI moves to the oldest pending decision, or to the empty state.
- **Toasts**: stacked above the submit button (`.actions`), at most 3 (bottom right only when nothing is shown). Answer / copy / "Delivered" (your own answer settled, or a background decision answered) last 2 seconds. When a decision that is not shown is lost (`answer_lost` / `hook_disconnected` / `fallback`, or `cancelled` after answering), a red 4-second toast says "<title> did not reach the agent (reason)". A decision that was never answered and became `cancelled` gives a red 4-second "<title> was cancelled".
- **Wide diagrams**: when a diagram's natural width exceeds 1.5x the column width, a "Full width f" chip appears. `f` (or the chip) hides the decision column and shows the diagram at full width (horizontal scroll if needed). While full width, `Enter` is disabled (no submit); `Esc` / `f` / `Tab` return. Switching decisions resets it.
- **"Scope and reversibility" in the right column** (plans): the section of that name in the plan body is shown above the buttons, folded at 8 lines (`.` or the chip expands). It is omitted when the section is missing. Code blocks over 9 lines fold into `<details>`.
- **Connection**: when SSE drops (including the first failure) a red banner "Cannot connect (<origin>). Reconnecting…" appears and the empty state says "Cannot connect". On recovery the banner clears and a green "Reconnected" toast shows for 2 seconds. On 401 the GUI refetches `GET /` to renew the cookie and retries once (still 401: "Reload the page"). SSE reconnects after 2 → 4 → 5 seconds (cap) and refetches the pending list on reconnect (vanished decisions are dropped).
- **Images**: only `data:` `<img>` survive in explanations (external, relative and same-origin `src` are removed). Inline `code` wraps at the column width (`overflow-wrap: anywhere`); words containing `-` (such as `--port`) are wrapped in a nowrap span with `<wbr>` between words so they are not split (`textContent` is unchanged; code inside `pre` is untouched). The `copy` event strips U+2060 from copied selections.
- **Connection banner layout**: `#banner` is row 1 of the `body` grid (normal flow). While shown it pushes the two columns (`main` / `.empty`) down, and no vertical scroll appears.
- Everything can be answered with the arrow keys alone. Controls show their key as a `<kbd>` chip. Question: `↑` / `↓` move (single select: move = select, stops at the ends), `Home` / `End` jump to first / last, `Space` toggles in multi select, `Enter` submits (on the free-text card with an empty field it focuses the field). In the field: `Esc` returns to the card, `↑` / `↓` return to the cards and move, `←` / `→` move the caret. Plan: `↑` / `↓` move between buttons and `Enter` decides (the `y` / `a` / `n` chips work too; `n` opens the reason field, `Esc` cancels). Common: `←` / `→` / `h` / `l` (`Tab` / `Shift+Tab`) previous / next pending, `b` opens the drawer, `.` expands or folds long sections, `c` copies the first code block (blocker), `f` toggles full width for a wide diagram. In the drawer: `↑` / `↓` (`j` / `k`) move, `Enter` switches, `Esc` / `b` / `←` close. Letter keys: `j` `k` `gg` `G` `i` for questions, `j` `k` `y` `a` `n` for plans. Movement keys work even when a button has focus. There is no fallback button (the API's `{fallback:true}` remains but the GUI never sends it).
- Each question card shows "Free text" under the options (a radio for single select, a checkbox for multi select) with a text input. When chosen, the answer value is that string (in multi select it is appended after the chosen labels). An empty string cannot be sent.
- `GET /` appends a version to the `app.js` / `app.css` URLs (`?v=<mtimeMs in base 36>`; `/public/*` ignores the query), and `app.js` shows a dim `build <v>` at the end of the hint line (bottom right in the empty state), so you can tell whether you are looking at a stale build.
