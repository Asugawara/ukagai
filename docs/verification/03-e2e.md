## Bugs found

| # | Severity | Description |
|---|---|---|
| B1 | **Important** | `install --data-dir <dir>` only reads the argument and does not pass it to the hook it registers (`src/settings/target.ts` has `dataDir`, but `src/settings/hooks-spec.ts` does not put `--data-dir` in args). When started with `serve --data-dir X`, the hook cannot read `~/.ukagai/token`, fails to authenticate, and **silently fails open**. Reproduction: `serve --port 4818 --data-dir /tmp/ukagai-v1` → install → AskUserQuestion in probe → does not appear in the GUI, normal UI. The cause is invisible to the user (whether doctor looks at `--data-dir` is unconfirmed) |
| B2 | **Important** | Stop's `escaped_question` detection is coarse and produces false positives on repeat-back or explanation sentences containing 「どちら」 (3/3). The denominator of (a') inflates, and with 3 answered + 1 fallback the rate becomes 0.43. This is as specified for the "coarse detection" in section 3 of the plan, but the dogfood metric is at an unusable level |
| F1 (known, fixed) | Important | ExitPlanMode was not registered in the GUI (400 on empty-string `explanation.path`). Reproduced in the first run of V1-3. The re-run after merging the fix confirmed that ExitPlanMode and loop_guard (both `path: ""`) appear in the GUI |
| B3 | Minor | In plan mode, SessionStart's advance instruction (write an explanation file) cannot be followed (plan mode blocks writes to the scratchpad). Separately from line 3 of the instruction, "no explanation file is needed for AskUserQuestion in plan mode", the instruction before ExitPlanMode is also ineffective in plan mode |
| B4 | Minor | The deny reason appears on the probe screen as `Error: PreToolUse:AskUserQuestion hook error: …`. To the user it looks like a hook error (same as T4 of 01. As specified) |
| B5 | Minor | `install --help` is unsupported (`不明な引数: --help`, i.e. "unknown argument: --help", exit 2). `ukagai --help` works |
